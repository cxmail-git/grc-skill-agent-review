# 四轮缺陷聚类与流程改进建议

> 对象：AI-GRC-KB v2 编译层 PH0 评审包（rev1→rev4）  
> 性质：第 5 轮复评前置材料 · 作者侧自检报告  
> 数据源：`04-完整评审报告`、`05/06/07-复评报告` 四份报告的缺陷清单全量条目  
> 生成日期：2026-10-29  

---

## 0. 一页结论

**四轮共 100 条缺陷，全部为机械可判类型，无一条属判定争议。**这条事实本身是本报告的核心结论：问题不在『规则设计难』，而在『工程纪律缺位』。

| 观察 | 数据 | 含义 |
|---|---|---|
| 缺陷总量 | 36 → 34 → 20 → 10 | 收敛成立，降幅 72%，但用了四轮 |
| Block 存量 | 10 → 8 → 3 → 2 | 两轮才从 10 降到 3，第 3、4 轮各剩 2 条 |
| **修复引入率** | 3/34 → 4/20 → 4/10（8%→20%→40%） | **边际修复效率在恶化**，逐条修下去会逼近 50% 返工 |
| 最大单类 | D 判据缺失 24 条、F 证据失实 24 条 | 一个伤『能不能判』，一个伤『判了能不能信』 |
| 最稳定复发通道 | B 规则-载体脱节 13 条（含 4 条 Block） | 每轮都有，靠人记忆无法消除 |
| 已被控住的通道 | E 仪器缺陷 1→2→3→1，rev4 仅 1 条 | **唯一样本：加反向基线后该通道即收敛**，可直接复制到其余通道 |

**结论三条：**

1. **不建议再做第 5 轮逐条修。**修复引入率已升至 40%，继续以『评审提一条、作者改一条』的方式推进，第 5 轮大概率仍是『修好的比新引入的多不了几条』。应改为一次性一致性重构（P-7）。
2. **74% 的缺陷可被前置脚本拦截。**A(19)+D(24)+E(7)+F(24)=74 条，均为结构化可校验项；剩余 26 条中 B、C 两类需人工影响面核对。当前 0 条前置拦截，全部靠外部评审发现，等于把机械劳动外包给了评审人。
3. **把『作者声明的可信度』当作独立质量维度管理。**F 类占比从 22% 升至 40%，即规则越修越对、报告越写越不准。这是评审信任崩溃的直接原因（rev2 的 MJ-03 预填 PASS、rev4 的 N-08 证据失实三处均属此类）。

## 1. 口径与分类体系

### 1.1 统计口径

- 取样范围：四份报告的**缺陷清单全量条目**，不含 PASS 项、不含 Pending 待裁定项。
- 计数单位：一条缺陷 = 一个编号（R-01…R-10、M-01…M-18、m-01…m-08、B-01…、MJ-01…、N-01…）。
- 分级沿用包内 `00-评审执行手册` §6：Block / Major / Minor。
- **主类归属规则**：一条缺陷只归一个主类，按『最接近其可执行修法的那一层』判定；跨类特征记在聚类小节，不重复计数。完整映射见附录 A，可逐条复算。

### 1.2 六类分类体系

| 类码 | 类名 | 判定问句（编制时自问） |
|---|---|---|
| A | 单一事实源失效 | 这个数字/名称/枚举，在包内是否只写在一处？ |
| B | 规则与载体脱节 | 规则改了，消费这条规则的数据、模板、fixture、清单是否同步改了？ |
| C | 规则间正面冲突 | 严格按 A 规则填，是否必然违反 B 规则？ |
| D | 判据与结构缺失 | 这条『必须』由谁判、输入是什么、闭合值域在哪、错误码是什么？ |
| E | 评审仪器缺陷 | 这条探针在合格包上真能 PASS、在反例上真能 FAIL 吗？ |
| F | 证据链与元陈述失实 | 这句话（引用/轮次/体积/『已全部修复』）背后有当轮实测输出吗？ |

设计取向：分类不是按『缺陷出现在哪个文件』，而是按**修复动作的类型**。同一类缺陷共享同一个修法、同一个防复发机制——这是后续所有流程建议能一一对号入座的前提。

## 3. 六类聚类详解

### 3.1 A 类 · 单一事实源失效（19 条，19%）

**定义**：同一个可计量事实（字段数、页数、体积、人日、名称集合、编号语义）在包内存在 ≥2 处写法且互不相等。

| 轮次 | 条目 |
|---|---|
| 第 1 轮（9） | R-01 字段模型四源、R-03 『13 条校验』两种构成、R-09 否决项 4/6 条、M-02 页数 10/12/15、M-14 成本 9.5/13.05/25/26、M-16 自述计数与体积、M-18 编号同名多义、m-01 P0 范围双源、m-06 无对象的 13 条 |
| 第 2 轮（8） | MJ-05 `SC-01`/`DP` 双重语义、MJ-09 同页 16/13 与 17/12、MJ-10 CK 名称 7/13 不一致、MJ-11 体积表 4 处、MJ-12 人审页数 10/11、MJ-15 约 20 处裸 `P0`、m-05 影响页数 3/2、m-09 字段名 `instrument_is_binding` 漂移 |
| 第 3 轮（1） | MJ-04 成本轮次『1 轮』与实际 2 轮 |
| 第 4 轮（1） | N-05 seed G0-1 与规划① 区间不等宽 |

**为什么能活到评审**：改数字时只改『当前正在看的那个句子』。包内同一个数字平均出现在 3–5 个位置（正文、表格、样例、对账表、README），且多数以自然语言嵌入，无占位符、无生成脚本；检索依赖人肉 grep，而人肉 grep 不会去查『同义改写』（如『10 页 fact-bearing』与『11 页人审』）。

**一个反直觉观察**：A 类在第 1 轮后被修掉了 90%，但 MJ-09 恰恰是**修 A 类时新造出的 A 类**（改章标题为 17/12，同页正文的两句没改）。这说明 A 类的修法本身不可靠，只要仍是手写，就会在下一轮以新形态回来。

**修法模式**：把数字从『内容』降级为『渲染结果』。所有计数、体积、人日、页数由 `tools/metrics.py` 计算并注入 `{{...}}` 占位符；未替换的占位符导致构建失败。命名类（CK 名、角色码、阶段码）维护一张 `glossary.csv` 作为唯一源，文档只允许引用、不允许复述。

### 3.2 B 类 · 规则与载体脱节（13 条，13%；含 4 条 Block）

**定义**：规则（schema/手册）已经改对，但消费该规则的数据实例（seed）、模板、fixture、评审清单未同步，导致『规则对、实例错』。

| 轮次 | 条目 | 性质 |
|---|---|---|
| 第 1 轮（4） | R-07 模板必填段无字段承载、R-10 P0 页违反自身触发条件、M-01 fixture 缺 KU、M-11 fixture 缺通用字段 | 规范与实例同时首建，天然错位 |
| 第 2 轮（4） | B-06 `rendered_blocks` 声明与实际块数不符（4/6 模板）、B-07 overview 页违反触发条件、m-06 『检查人：S1』、m-07 样例 hash 8 位 | **本轮新增规则未回灌载体** |
| 第 3 轮（4） | B-01 locator 新值域未回灌（5/10 KU 违规）、B-02 source 模板更新记录、MJ-05 邀请仍写 `SC-01`、m-09 样例 `gap.owner: S1` | 同上，且 MJ-05 已修过一次仍残留一处 |
| 第 4 轮（1） | N-01 B-group 未回灌，B1/B3『应 PASS』现同时违反两条新规 | 同上 |

**为什么这是最危险的一类**：它直接产生 Block。四轮 23 条 Block 中有 4 条明确属 B 类（B-01/B-02 rev3、N-01 rev4、B-06 边缘），且**每一轮的 Block 主源几乎都是它**。更关键的是它**无法靠自检发现**——作者改规则时看到的是规则，看到实例的那一眼已是十分钟前。

**典型失效链（rev3 → rev4，N-01）**：

```
修 MJ-02『检查人必须实名』
  → 改 schema §6.1 判据（对）
  → 改 CK-09 交叉比对（对）
  → 未改 fixtures/B-group.md B1/B3 的『检查人：R-1』
  → 该 fixture 从『应 PASS』变成『应 FAIL』
  → 评审方按 fixture 跑，得出规则与示例互斥 → 新 Block
```

**修法模式（唯一可靠的做法）**：修改任何规则前，先执行『消费点枚举』——`grep -rn` 该规则的编号、字段名、示例值，得到消费点清单，逐项标注『已改 / 不适用+理由』，形成 `impact-matrix` 并随修订提交。缺此项视为修订不完整。这一条不做，第五轮一定会再出 B 类。

### 3.3 C 类 · 规则间正面冲突（13 条，13%）

**定义**：单独看每条规则都成立，但组合起来对某个正常输入无解——严格按模板填必然违规，或按一条规则合规必然违反另一条。

| 轮次 | 条目 | 冲突对 |
|---|---|---|
| 第 1 轮（5） | R-04、R-05、R-06、M-08、M-09 | 措辞规则 vs 字段模型；§6 必填段 vs WS-02；hash 覆盖范围；『不可比不得为空』 vs 无合法空值 |
| 第 2 轮（6） | B-01~B-04、MJ-06、m-11 | title 分类两规范相反；front-matter 与扫描面；合法『无』式含日期；派生块内『无』式 vs 渲染输出等价；『选择建议』 vs 禁结论；模板 page_id 两说 |
| 第 3 轮（1） | B-03 | EX-5/EX-6 构成单点绕过通道 |
| 第 4 轮（1） | N-02 | DF-4b 显式豁免『强制/自愿』，而 comparison 模板明令其为 NARRATIVE_FACT |

**为什么难发现**：冲突分布在两个文件、两个章节，且都写得『很合理』。评审方是靠『把 A2 场景手填一遍』（D2 实测）才暴露的——这说明**冲突检测的有效手段是『构造一个实例跑通』，而不是『再读一遍规则』**。

**一个警示样本（N-02）**：上一轮评审要求『给分类词可执行判据』（MJ-03），作者新增 DF-4b 并写成『分类用语豁免』。这一改法在语法上满足了要求，在语义上却把被禁止的措辞合法化——**修法满足了字面要求、违反了原意**。这类返工靠 '逐条对账' 永远查不出来，只有靠『改动前后跑同一组 fixture 比对结果』才能发现。

**修法模式**：维护 `rule-matrix`（规则 × 模板 × fixture），每次改规则必须重跑全量 fixture 并 diff 判定结果；任何 fixture 判定由 PASS 翻 FAIL 或反向翻转，都必须显式说明。

### 3.4 D 类 · 判据与结构缺失（24 条，24%；最大单类）

**定义**：规则只写了『必须/不得/应当』，但没有给判定主体、输入对象、闭合值域、错误码中的一项或多项，导致规则事实上不可判。

| 轮次 | 条目 |
|---|---|
| 第 1 轮（9） | R-02 `render_hash` 无定义、R-08 G0 无法通过、M-03 模板注释强制项未入 schema、M-04 front-matter 契约、M-07 抽样入禁、M-10 义务簇无定义、M-12 conflicts 结构、M-13 缺错误码、m-07 术语无定义 |
| 第 2 轮（7） | B-05 DF 判据不在包内（V1 实质复发）、B-08 G0 判据子集、MJ-01 允许字段集表缺失、MJ-02 `gap` 不在字段表、MJ-07 `refs.json` 无结构、MJ-13 B 判决未约束 Pending、m-10 第三支不是段落写法 |
| 第 3 轮（6） | MJ-01 G0 缺 CK-11/12、MJ-02 『实名』无判据、MJ-03 分类词无判据、m-01 输出码不在错误码表、m-10 验收映射缺项、m-12 『CK-08 覆盖字段值』名不副实 |
| 第 4 轮（2） | N-03 三处新判据只写散文、N-04 `log.md` 无结构定义 |

**为什么它是最大类且最难收敛**：D 类的修法天然是『再加一段说明』，而**说明本身不是判据**。rev3 的三处新判据全部写在散文里（N-03），rev4 的 `log.md` 被依赖却无结构（N-04）——同一个错误连续两轮以不同外衣出现。

**结构性原因**：包内已有一条很好的原则（BL-3『缺判据即规则不成立』），但它只写在手册里，**没有变成编写模板的强制字段**。规则表 `CK` 只有『编号/名称/判据』三列，缺『判定主体』『输入与扫描面』『错误码』三列——于是写出不可判规则不需要付出任何代价。

**修法模式**：把 BL-3 从『原则』变成『表结构』。CK 表强制六列（编号 / 名称 / 判定主体 auto|manual / 输入与扫描面 / 闭合判据 / 错误码），任一列空则该规则不得进 §8 门禁。修完跑一条自校验：`CK 行有空格列 == 0` 且 `错误码表 ↔ CK 引用双向可解析`。

### 3.5 E 类 · 评审仪器缺陷（7 条，7%）

**定义**：探针、grep 命令、fixture 期望值本身有问题——命令命中了自身或历史说明（自命中）、正则匹配不到实际语序（盲区）、期望值与合格包实际不符（假红/假绿）。

| 轮次 | 条目 | 缺陷形态 |
|---|---|---|
| 第 1 轮（1） | M-17 | 探针选错对象：查 certification，而包内刻意无此页 |
| 第 2 轮（2） | MJ-04（4 条 grep 全部有缺陷）、MJ-08（A2 标 CK-13，实为人工判） | 自命中 + 可判性误标 |
| 第 3 轮（3） | m-02 复验命令重复计数、m-03 C0 实跑 17 处、m-04 C3/C5 字面自命中 | 期望值未实测 |
| 第 4 轮（1） | N-07 C5-3 实跑 1 命中而基线表记 PASS；C5-2 双重盲区 | **基线表记录与实跑不一致** |

**这一类是整个包里唯一『被真正治住』的通道**：数量 1→2→3→1，且第 4 轮那 1 条是遗漏而非新机制问题。原因是 rev3 起引入了『反向基线』——先在故意破坏的副本上跑出 FAIL，再在合格包上跑出 PASS，两段输出都落盘。**这是可复制的成功经验，应当推广到 A/B/C/D/F 五类。**

**留一个教训**：N-07 的根因不是探针写错，而是**基线表照抄了上一轮结论**。即『证据文件也会失实』——所以证据必须是当轮命令的原始输出（带时间戳），不能是人工转写的一句话。

### 3.6 F 类 · 证据链与元陈述失实（24 条，24%，且逐轮上升）

**定义**：文档中的陈述与事实不符——引用章节号错、轮次标错、体积/计数过时、『已全部关闭』类绝对断言无据、预填结论、声明与包内容矛盾。

| 轮次 | 条目 |
|---|---|
| 第 1 轮（8） | M-05 AIGC 水印与页脚、M-06 依赖未交付、M-15 以不可判否决项作推理、m-02 判定列混装、m-03 空占位称示例、m-04 文件名不存在、m-05 非法判定词、m-08 删除承诺无登记 |
| 第 2 轮（7） | MJ-03 结论页预填 4 项 PASS、MJ-14 『不含任何过程记录』与对账表矛盾、m-01~m-04 四处 § 引用错位、m-08 编号错位 |
| 第 3 轮（5） | m-05 成本位置引用错、m-06 轮次标『第 2 轮』、m-07 对账表描述不全、m-08 文件头归因错配、m-11 WS-09 指向无维度表的 CK-02 |
| 第 4 轮（4） | N-06 §G0-④ 应为 ⑥、N-08 对账表证据失实三处、N-09 陈旧文本（清单标题 rev2 / 第 3 轮 / G0 四条）、N-10 glossary 指向缺失 |

**为什么它比看起来严重**：F 类几乎全被判为 Minor，但它破坏的是**评审的可信基础**。rev2 的 MJ-03（结论页预填 4 项 PASS）如果没被发现，整轮评审就变成走过场；rev4 的 N-08（对账表称『仅命中 1 处』实为 4 处、称『已同步』实未改）如果没被发现，下一轮复评会基于假前提展开。**规则错可以改，账实不符会让所有后续判断失效。**

**结构原因**：文档被当作『叙述载体』而非『证据载体』。绝对化措辞（全部、唯一、仅、不含任何）写作成本极低、核查成本极高；元信息（rev 标签、轮次号、章节号）在每次改版后都需要人工同步，而无任何 lint。

**修法模式**：

1. 绝对化词表 + 强制证据位：凡出现『全部/唯一/仅/不含任何/已关闭』，同句必须带 `→ 证据：<命令> @ <时间>`，否则删除或降级为『据 X 表第 N 行』。
2. 元信息 lint：rev 标签、轮次号、章节号、文件名存在性、数字占位符残留，一次性脚本校验。
3. 禁止预填任何判定结论；结论页只允许写『复验指引』。

## 4. 根因：五条机制，一条链

聚类只是现象。把 100 条压到机制层，只有五条，且彼此串联：

| 编号 | 机制 | 支撑类 | 证据 |
|---|---|---|---|
| G-1 | **规范与实例双轨编辑，无影响面枚举**——规则与消费它的数据/模板/样例由不同文件承载，改动无检索清单 | B（13）、A（部分） | 四轮均有 B 类，且 4 条 Block 由此产生；MJ-05 修过一次仍残留一处 |
| G-2 | **规则只有约束句，没有判定四要素**——判定主体/输入/闭合值域/错误码未强制 | D（24）、C（部分） | D 是最大类；BL-3 原则未进表结构 |
| G-3 | **校验器与被校验对象同处一包，无隔离**——模式串、期望值、基线表与被检文本互相污染 | E（7） | 四轮均有自命中；N-07 为基线表照抄 |
| G-4 | **元信息无生命周期**——rev 标签/轮次/章节号/计数随改版漂移，无 lint | F（24）、A（部分） | F 占比 22%→40% |
| G-5 | **作者自评替代独立复核，且不要求证据留痕**——修完由作者声明『已修』，无当轮实测输出 | F（主要）、E（部分） | MJ-03 预填 PASS；N-08 三处证据失实；T0『20/20 已修』与本节不符 |

**因果链（这张链解释了为什么四轮才收敛）：**

```
G-2 判据缺失
   └→ 规则不可自动判 → 只能人判
        └→ 人判依赖文档陈述 → G-5 无证据要求
             └→ 陈述失实（F）不被发现 → 评审结论建立在假前提上
                  └→ 结论偏差 → 下一轮返工（修复引入率 40%）
G-1 无影响面枚举
   └→ 每次修规则都新增 B 类 → 新一轮 Block → 再修 → 再引新缺陷（闭环）
G-3 仪器污染 + G-4 元信息漂移
   └→ 探针假绿 / 引用错位 → 本可前置拦截的缺陷漏到评审
```

**一句话**：这不是『设计能力不足』，是**缺少一条把设计固化为可执行契约的工程流水线**。四轮里没有一条缺陷需要重新做架构决策，全部是执行与核对问题。

## 5. 流程改进建议（P-1 ~ P-7）

设计原则：**每条建议必须能对应到具体的缺陷类、有可测的验收判据、有明确的不通过后果。**不设"加强重视""提高质量意识"这类无法执行的条目。

### 5.1 总览与优先级

| 编号 | 措施 | 对应类 | 可拦截条数 | 一次性成本 | 每轮增量成本 | 优先级 |
|---|---|---|---|---|---|---|
| P-1 | 数字与命名生成化（占位符 + glossary 单一源） | A | 19 | 0.5 人日 | ≈0 | P1 |
| P-2 | 变更影响面矩阵（impact-matrix 门禁） | B | 13（含 4 Block） | 0.25 人日 | 0.25 人日/轮 | **P0** |
| P-3 | 规则四要素表结构 + 冲突矩阵回放 | D、C | 37 | 1.5 人日 | 0.25 人日/轮 | **P0** |
| P-4 | 探针工程化（正/反基线 + 模式文件化） | E | 7 | 0.75 人日 | ≈0 | P1 |
| P-5 | 证据链与元信息 lint | F | 24 | 0.5 人日 | ≈0 | P1 |
| P-6 | 角色分离与证据留痕（治理） | F、E 的放大器 | 间接 | 0 | 0 | P1 |
| P-7 | 一次性一致性重构替代逐条修 | 全部（返工率） | — | 1.5 人日 | — | **P0** |

合计一次性投入约 **5 人日**（其中 P-2/P-3/P-7 合计 3.25 人日为必做）。对照基准：包内自报四轮累计已投入 **20.30 人日**（12.75 编译 + 6.00 评审 + 1.55 修复），且尚未拿到无条件通过。以 5 人日换掉 74% 的返工面，投入产出比无疑。

### 5.2 P-2 · 变更影响面矩阵（最高优先级）

**这是唯一直接消灭 Block 的措施，必须最先做。**

规则层任何改动，提交时必须附一张 `impact-matrix`：

| 规则号/字段 | 消费点（文件:行） | 处理 | 证据 |
|---|---|---|---|
| CK-09 检查人实名 | `fixtures/B-group.md:16` | 已改为实名 | 该 fixture 重跑：PASS |
| CK-09 检查人实名 | `fixtures/B-group.md:52` | 已改为实名 | 同上 |
| CK-09 检查人实名 | `templates/source.md:44` | 不适用（模板用槽位） | 说明 |

三条硬规则：

1. **消费点必须用 grep 枚举，不得凭记忆填写**。枚举命令固化为 `tools/consumers.sh <symbol>`，输出即矩阵骨架。
2. **每行必须有『处理 + 理由』**，`不适用` 也要写理由。
3. **改动后必须重跑全量 fixture，并 diff 判定结果**。任何 PASS→FAIL 或 FAIL→PASS 的翻转都要在矩阵末尾单列说明；未说明的翻转视为引入回归缺陷，评审方直接判 Block。

依据：rev3 的 B-01/B-02、rev4 的 N-01 全部是"改了规则没改实例"。这一条坚持执行，B 类可归零。

### 5.3 P-3 · 规则四要素与冲突矩阵

**（a）CK 表六列强制**

现表为三列（编号/名称/判据），扩为六列，缺列即不得进 §8 门禁：

| 列 | 要求 | 反例（历史实际发生） |
|---|---|---|
| 编号 | `CK-NN`，全包唯一 | 编号同名多义（M-18） |
| 名称 | 与记录表 §4 逐字一致 | 13 项名称 7/13 不一致（MJ-10） |
| **判定主体** | `auto` / `manual` / `auto+manual` | CK-13 冲突存在性声称自动，实为人工（MJ-08） |
| **输入与扫描面** | 明确到段落/字段，含排除集 | front-matter 与 WS-02 扫描面冲突（B-02） |
| **闭合判据** | 正则或闭合值域表（表须在包内） | 『实名』无判据（MJ-02 rev3）；允许字段集表缺失（MJ-01 rev2） |
| **错误码** | 必须在 §10 错误码表中存在 | 输出 `GAP_UNKNOWN_FIELD` 而表中无此码（m-01 rev3） |

配套自校验两条（脚本化，0 成本）：

- `CK 行存在空列 == 0`
- `CK 引用错误码 ↔ §10 错误码表` 双向差集为空

**（b）冲突矩阵回放**

维护 `rule-matrix`：行 = 规则，列 = 六类模板 + 全部 fixture，格 = 该规则对该对象的判定（PASS/FAIL/NA）。每轮改版后整表重跑，任一格翻转即须解释。

依据：R-05/R-06/M-09/B-01~B-04/MJ-06/N-02 这 13 条冲突，全部是"单条读都对、组合无解"。只有把实例跑一遍才会暴露——D2 实测手填之所以有效，正是因为它无意中做了这件事，应把它制度化。

### 5.4 P-1 · 数字与命名生成化

- 所有可计量事实从『正文内容』降级为『渲染变量』：`{{ku_total}}`、`{{fb_fields}}`、`{{pkg_bytes}}`、`{{effort_total}}`、`{{review_round}}`、`{{rev_label}}`。
- `tools/metrics.py` 负责计算并注入；构建时若存在未替换占位符 → 构建失败（不允许"先发出去再改"）。
- 命名类（CK 名、角色码 `R-*`、阶段码 `PH0–PH4`、错误码）维护 `glossary.csv` 唯一源，正文只允许引用编号，复述即违规（由 P-5 的 lint 抓）。
- 体积表、成本表、页数表、勾选项计数一律脚本生成，**禁止手写**。

依据：A 类 19 条中，体积/计数/页数/成本四项占 11 条，且 MJ-11 的偏差只有 203 B——人手根本算不准，也不该算。

### 5.5 P-4 · 探针工程化

把散落在清单里的 grep 命令收进 `probes/`，每条探针三件套：

| 组成 | 要求 |
|---|---|
| `pNN.pattern` | 模式串独立文件（避免命令自身被匹配；解决自命中） |
| `pNN.exclude` | 排除集**白名单文件**，不用 `grep -v` 手写串（历史多次因排除集不全而假绿） |
| `pNN.expect` | 期望结果（命中数/命中行集合），由脚本断言而非人眼比对 |
| `pNN.neg` | **反向用例**：在故意破坏的副本上必须 FAIL |

执行纪律：新增探针必须先跑反向用例，能 FAIL 才允许进正文表格；正反两段原始输出（含时间戳）落盘 `evidence/pNN_<rev>.log`，基线表只准引用日志，不准人工转写。

依据：这是四轮中唯一被验证有效的治理动作——E 类从 3 条降到 1 条（N-07 还是因为基线表照抄而非探针本身）。N-07 的教训要求再加一条：**基线表与 `evidence/` 日志不一致，直接判 Block**（因为这意味着所有 PASS 都不可信）。

### 5.6 P-5 · 证据链与元信息 lint

交付前跑 `tools/lint_docs.py`，命中任一项即禁止送出：

| 检查 | 规则 | 对应历史缺陷 |
|---|---|---|
| 绝对化措辞 | 『全部/唯一/仅/不含任何/已关闭/已清零』须同句带 `→ 证据：<命令> @ <时间>` | N-08、MJ-14、T0『20/20 已修』 |
| 轮次一致性 | 正文轮次号 = 结论页 = 对账表 = 文件头，四处一致 | m-06 rev3（第 2 轮 vs 第 3 轮）、N-09 |
| rev 标签 | 文件名、页首 H1、页内自称三处一致 | 5 文件 H1 仍为 rev3（rev4 修复项） |
| 章节引用存在性 | 所有 `§X.Y` 解析到目标文件实际标题 | m-01~m-04 rev2、N-06 |
| 文件名存在性 | 所有反引号内的路径真实存在 | m-04 rev1 |
| 占位符残留 | `{{...}}` 计数为 0 | P-1 配套 |
| 禁用词 | 按 glossary 的禁用清单（裸 `P0`、『零余量』、`S1` 作人名等） | MJ-15、m-05 rev1、m-06 rev2 |

### 5.7 P-6 · 角色分离与证据留痕

三条制度：

1. **作者不得自评结论**。作者只提交『对账表 + 当轮命令日志』；结论页只允许写『复验指引』。凡预填 PASS 即判 Block（历史：MJ-03 rev2）。
2. **探针由非作者执行**。作者自跑的结果仅作参考，评审方独立重跑并比对；两者不一致时以评审方为准并追溯原因。
3. **Block 关闭需两条独立证据**：规则侧（条文已改）+ 载体侧（实例重跑）。缺一条只能记『部分』，不能记『已修』。历史多次把『部分』写成『已修』（N-08 的 T0、T2），根因就是只查了规则侧。

### 5.8 P-7 · 用一次性重构替代逐条修（节奏建议）

**不建议再做第 5 轮『评审提一条、作者改一条』。**理由已在 §2.4 给出：返工率 8%→20%→40%，继续下去修复动作本身将超过评审发现量。

建议改为一个 1.5 人日的**一致性重构 sprint**，只做四件事，不做任何新增设计：

| 步骤 | 内容 | 产出 |
|---|---|---|
| S1 | 建 `glossary.csv` + `tools/metrics.py`，替换全部手写数字与复述命名 | 全包占位符化 |
| S2 | CK 表扩六列，补齐空格；错误码双向对齐 | 规则层可自动判 |
| S3 | 跑 `consumers.sh` 全量枚举，逐条回灌 seed / 模板 / fixtures / 清单 / 邀请 / 结论页 | impact-matrix 100% 有『处理』 |
| S4 | 探针迁入 `probes/`，全量跑正/反两段，日志落 `evidence/` | 基线表全部有日志支撑 |

完成后打 `v2.0-freeze` 标签，此后**只接受不改变语义的更正**，任何语义变更走下一阶段（PH1）排期。冻结是收敛的前提——四轮里之所以反复，一部分原因就是每轮都允许在修缺陷的同时顺手改设计（N-02 就是"顺手把 MJ-03 改反方向"）。

## 7. 度量与预期

### 7.1 建议纳入每轮评审首页的六个指标

| 指标 | 定义 | 当前值（第 4 轮） | 目标 |
|---|---|---|---|
| 缺陷总量 | 本轮新增缺陷条数 | 10 | ≤2 |
| Block 存量 | 未关闭 Block 数 | 2 | 0 |
